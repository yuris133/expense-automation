# Автоматизация учёта чеков: как помогать с проектом

Проект принимает кассовые чеки (фото через Telegram-бот, PDF, файлы из папки),
извлекает позиции, раскладывает по статьям бюджета и строит отчёты.

## Архитектура (запомнить порядок)

```
вход: Telegram-бот / папка receipts/ / ingest.py
  → prepare_receipts.py   (EXIF-разворот, чтение QR)
  → fetch_detail.py       (официальные позиции по фискальным признакам; лимит 15/сутки)
  → parse_pdf.py          (PDF с текстовым слоем)
  → extract_items.py      (OCR с картинки — резерв, помечает на проверку)
  → data/positions.json   (источник правды)
  → build_report.py       (Excel 5 листов + CSV-снимок)
  → build_dashboard.py    (HTML-дашборд)
```

Бот (`src/telegram_bot.py`) после каждого принятого чека сам запускает конвейер.
Ручной эквивалент: `python src/run_pipeline.py`.

## Ключевые факты

- Файл проекта чеков/позиций: `data/positions.json` — структура `{"receipts": [...], "items": [...]}`;
  `category` позиций можно править, явное значение имеет приоритет над автоопределением.
- Справочник статей: `config/categories.json` — коды, названия, ключевые слова
  и правила приоритета для спорных категорий.
- Дедупликация по SHA-256 (`data/seen_hashes.json`) — повторные чеки не задваиваются.
- Квота детализации: `data/api_quota.json`, ~15 чеков/сутки, ротация в 00:00 МСК;
  при исчерпании бот копит чеки в очередь и разбирает после возобновления.
- Дата в отчётах — готовым текстом `ДД.ММ.ГГГГ` (специально для вьюеров Apple);
  в JSON она может выглядеть иначе (`2026-07-22 20:23`, `20260722T2023`) — конвейер нормирует.
- Дашборд — снимок: не обновляется сам, пересобирается конвейером или `python src/build_dashboard.py`.
- Параметры ссылки дашборда: `?theme=light|dark`, `?agg=week`.
- Группы доступа: `config/access.json`, `users` = числовые chat_id, `usernames` = без @;
  аккаунт видит только свою группу (`groups/<код>/...`). Изменение конфига — перезапуск не нужен.
- Автозапуск Windows: задача Планировщика `ReceiptsBot` (создаёт `scripts/setup_autostart.bat`);
  всегда только один экземпляр бота — два делят канал Telegram.

## Типовые задачи

### Пересобрать отчёты
```powershell
python src/run_pipeline.py
```
Если правили только дашборд-вход (`data/positions.json`) руками — то же самое;
если чеков нет — пустой прогон безопасен.

### Разобрать конкретный чек вручную
Положить файл в `receipts/`, затем `run_pipeline.py`. Если QR не читается —
`python src/extract_items.py --image <файл>` и сверить результат руками.
OCR-позиции помечены в `comment` — их проверяют выборочно, а не доверяют вслепую.

### Добавить/уточнить статью бюджета
Править `config/categories.json` (ключевые слова, приоритеты), затем пересобрать
отчёт. Существующую разметку это **не перезаписывает** — уже размеченные позиции
остаются; переразметить конкретную позицию — правкой в `data/positions.json`.

### Расход без чека
Командой бота `/add 500 обед при встрече` или сообщением «500 обед при встрече»;
программно — запись в `data/positions.json` + `run_pipeline.py`.

### Диагностика бота
Сначала `logs/telegram_bot.log` и `logs/bot_console.log`, затем — жив ли процесс
(двойной запуск запрещён), валиден ли токен в `config/telegram.json`,
не исчерпана ли квота (`/status` показывает лимит).
Самопроверка: `python src/self_test.py`; изоляция групп: `python src/access_audit.py`
(прогонять после правок бота — любой FAIL = утечка чужих данных).

### Приём чеков из внешнего места (облако, почта)
```powershell
python src/ingest.py --from "ПУТЬ\к\папке" --move --run
```

### Перенос на сервер 24/7
Конфигурации в `deploy/`: Oracle Always Free (`README_Oracle.md`), Fly.io (`README_Fly.md`),
Google Cloud (`README_Google.md`). Токены на сервере — через переменные окружения /
`/etc/receiptsbot.env`, не в конфигах. Перед переездом остановить локального бота:
`schtasks /Delete /TN "ReceiptsBot" /F`.

## Правила безопасности

- Не коммитить и не копировать куда-либо файлы `config/telegram.json`,
  `config/proverkacheka.json` с реальными токенами и `config/access.json` с реальными
  chat_id — при раздаче проекта выписывать их с заглушками.
- Демо-прогон `python src/build_report.py --demo` не трогает пользовательские данные —
  безвреден для проверки установки.

## Правила работы

- Правки в `data/positions.json` подтверждать пересборкой (`run_pipeline.py`) и
  показывать пользователю разницу (например, счётчики чеков/позиций до и после).
- Перед правкой чужих данных (позиции, группы) показывать затрагиваемые фрагменты.
- OCR-результат всегда предлагать сверить глазами: точность помечена в `comment`.
